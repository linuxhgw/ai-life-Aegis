# Aegis 个人生活助手 — 学习路线

> 本文档基于 `基于hermes的个人生活助手方案.md` 和 `全自主开发的个人生活助手方案.md` 提炼，为实现 Aegis 项目你需要掌握的知识体系。
>
> **两个方案的技术栈差异巨大**，请先选择路线再按图索骥：
> - **Aegis-Hermes 路线**：依赖 Hermes 框架，自研部分少，适合快速落地（约 8 周 MVP）
> - **Aegis-Native 路线**：全自研 Rust 内核，技术深度要求高，适合长期主义（约 14 周 MVP）
>
> 无论选哪条路，**基础层完全相同**，分歧从第五阶段开始。

---

## 概览：五阶段学习路径

```
阶段一（地基）    阶段二（客户端）    阶段三（核心）    阶段四（AI集成）    阶段五（选路）

编程基础                                    →               →               →

系统 API          Win32 / Android       规则引擎           记忆系统           →

```

## 阶段一：编程基础（共 4 周）

**目标**：能读懂代码、能写脚本、能理解跨进程通信。

### 1.1 Python（走 Hermes 路线必深入，走 Native 路线也需能用）

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| 语法 & 数据结构 | 能独立写脚本，处理 JSON / 文件 / HTTP | 《Python Crash Course》或官方教程 |
| 异步编程 `asyncio` | 理解协程、Task、事件循环；能写 MCP Server 的 async 入口 | [Real Python - Async](https://realpython.com/async-io-python/) |
| 类型注解 `typing` | 读懂带泛型的 Python 类型签名 | 官方 typing 模块文档 |
| HTTP 客户端 `httpx` | 能调用 Ollama API、发送 Webhook | httpx 官方文档 |
| SMTP / email | 能用 `smtplib` 发送邮件 | Python `smtplib` 标准库文档 |

**验收标准**：能独立写一个 MCP Server（接受 STDIO 输入，返回 Tool Result）。

### 1.2 Rust（Native 路线核心，Hermes 路线了解即可）

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| 所有权、借用、生命周期 | 能写不 panic 的基本程序 | [The Rust Book](https://doc.rust-lang.org/book/) ch3-10 |
| 错误处理 `Result`、`?` | 理解 `thiserror` / `anyhow` 的使用场景 | [Rust error handling](https://doc.rust-lang.org/book/ch09-00-error-handling.html) |
| 异步编程 `tokio` | 理解 `async fn`、任务调度、`Arc<Mutex<T>>` | [tokio 文档](https://tokio.rs/tokio/tutorial) |
| 宏和 trait | 理解 `#[derive(...)]` 机制，能读懂 tonic 生成的代码 | The Rust Book ch19 |
| FFI / C 互调 | 理解 `#[repr(C)]`、链接 C 库 | [Rustonomicon](https://doc.rust-lang.org/nomicon/) |

**验收标准**：`cargo new aegis-core --bin` 能编译运行，且能引入 `tokio` 和 `tonic` 并启动 gRPC 服务。

### 1.3 网络协议基础（共用）

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| HTTP / REST | 理解请求/响应模型、状态码、JSON 序列化 | MDN Web Docs |
| WebSocket | 理解全双工通信，能用 `tokio-tungstenite` 写服务端 | tokio-tungstenite 示例 |
| gRPC / Protobuf | 理解 Proto 文件语法、服务定义、代码生成 | [gRPC 官方文档](https://grpc.io/docs/) |
| mDNS / DNS-SD | 理解局域网设备自发现原理 | Bonjour/Avahi 文档 |
| TCP / UDP 基础 | 理解端口、连接建立、粘包问题 | 《计算机网络：自顶向下方法》 |

**验收标准**：能用 Protobuf 定义一个 `AegisEvent` 消息，用 tonic 编译并写出 gRPC 服务和客户端。

### 1.4 Git 与协作

| 主题 | 深度目标 |
|------|----------|
| Git 基础 | add / commit / push / branch / merge / rebase |
| Git 高级 | submodule（如 MCP Server 作为独立仓库）、git hook |
| 项目管理 | 用 GitHub Issues / Projects 追踪任务 |

**验收标准**：提交符合本项目 `docs/CLAUDE.md` 中的规范（type + scope + subject）。

## 阶段二：客户端开发（共 4 周）

**目标**：能写出 Windows 桌宠和 Android 悬浮球。

### 2.1 Tauri 2.0 桌面端（Windows 桌宠）

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| Tauri 基础 | 创建项目、构建可执行文件、签名 | [Tauri 2.0 官方文档](https://v2.tauri.app/) |
| Rust 后端 | 定义 Tauri Command、实现全局热键 `RegisterHotKey` | `tauri-plugin-global-shortcut` |
| Web 前端 | 用 HTML/CSS/JS 或 React 写透明窗口、Live2D 嵌入 | 任意前端框架 |
| WebSocket 通信 | 与 Hermes Gateway 或 Aegis Core 建立长连接 | 前端 `WebSocket` API |
| 窗口管理 | 透明窗口、置顶窗口、多���示器支持 | Windows API `SetWindowPos` |

**验收标准**：桌宠在桌面透明显示，能响应热键触发弹窗，能通过 WebSocket 收发消息。

### 2.2 Flutter 移动端（Android 悬浮球）

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| Flutter 基础 | Widget 体系、状态管理（Provider/Riverpod） | [Flutter 官方 codelab](https://docs.flutter.dev/codelabs) |
| Android 系统窗 | 悬浮球、遮罩层、全屏 Dialog | `android.widget.PopupWindow` / `android.view.WindowManager` |
| Flutter Platform Channel | Dart 与 Kotlin/Swift 互调 | [Platform channels](https://docs.flutter.dev/platform-integration/platform-channels) |
| gRPC 客户端 | Flutter 中调用 gRPC 服务 | `dart gRPC` 库 |
| 后台保活 | Android Service、Foreground Service、前台通知 | Android 官方文档 |

**验收标准**：悬浮球可在任意 App 上层显示，点击展开菜单，划动可拖拽，通过 gRPC 与 PC 通信。

### 2.3 系统级 API（共用）

| 平台 | 技能 | 用途 |
|------|------|------|
| **Windows** | Win32 API（`user32.dll` / `kernel32.dll`） | 进程枚举、窗口操作、锁屏、挂起进程 |
| **Windows** | DXGI / GDI 截屏 | 屏幕内容捕获（感知层） |
| **Android** | LSPosed / Xposed Hook | 拦截 `startActivity`、系统级遮罩 |
| **Android** | AccessibilityService | 无 Root 下的前台 App 检测（降级方案） |
| **Android** | ADB Shell（Root） | `am force-stop`、截屏、文件推送 |
| **Android** | AIDL / Binder IPC | Kotlin Daemon 与 Flutter 通信 |

**验收标准**：无 Root Android 能检测前台 App（Accessibility）；有 Root Android 能拦截 App 启动并弹出系统级遮罩（LSPosed）。

## 阶段三：核心引擎（共 3 周）

**目标**：理解 Agent 系统的认知层，无论用 Hermes 还是自研都需掌握。

### 3.1 MCP（Model Context Protocol）

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| MCP 协议规范 | 理解 `tools/call_tool`、`resources`、`prompts` 三类入口 | [MCP 官方 Spec](https://modelcontextprotocol.io/) |
| MCP Server 开发 | 用 Python `fastmcp` 或 Rust `rmcp` 实现 Server | 各自 GitHub 仓库示例 |
| MCP 客户端 | Hermes 内置支持；自研则用 `mcp-client` 库连接 | - |

**验收标准**：写一个 `intervention.show_popup` 工具，Hermes 能调用它弹窗。

### 3.2 规则引擎

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| DSL 设计 | YAML DSL 语法设计（条件/动作/优先级/冷却） | 参考本项目 `rules/focus_guardian.yaml` |
| 表达式解析 | 实现 `eq` / `in` / `between` / `lt` 等操作符 | 用 `rhai` 脚本引擎 或手写表达式解析器 |
| JIT 编译 | YAML → Rust 闭包 / `rhai` 脚本执行 | rhai 文档 |
| 规则编排 | 命中后动作链、fallback 机制、原子事务 | - |

**验收标准**：写一条 `工作时间禁止娱乐 App` 规则，响应时间 < 10ms（不经过 LLM）。

### 3.3 状态机设计

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| 有限状态机 | 状态定义、转换条件、进入/退出钩子 | 《游戏编程模式》- 状态机章节 |
| 自适应状态 | 根据历史数据动态调整状态转移阈值 | 强化学习基础概念 |
| 分级干预 | Level 1~5 的状态定义和升级路径 | 本项目状态机设计 |

**验收标准**：实现完整的状态机，能响应 `用户关闭弹窗` → 升级到 Level 3，并在数据库记录转移。

### 3.4 数据库与存储

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| SQLite | 建表、索引、事务、备份 | sqlite3 官方文档 |
| 向量存储 `sqlite-vec` | 本地向量嵌入存储和检索（替代 PGvector） | [sqlite-vec GitHub](https://github.com/asg017/sqlite-vec/) |
| ORM / 查询构造 | 避免手写 SQL 拼接，用 `rusqlite` 参数化查询 | rusqlite 文档 |
| 事件溯源 | 只增改日志设计，全量历史可查 | 事件溯源（Event Sourcing）模式 |

**验收标准**：能查询"今天第几次打开娱乐 App"、"上次类似场景用了什么干预级别"。

## 阶段四：AI 集成（共 3 周）

**目标**：让 LLM 成为决策引擎，理解 Agent 的思维方式。

### 4.1 本地 LLM（Ollama / vLLM）

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| Ollama 部署 | 拉取模型、启动服务、API 调用 | [Ollama 官方文档](https://github.com/ollama/ollama) |
| 模型选型 | 推理能力 vs 速度权衡：`qwen2.5:14b` / `llama3.1:8b` / `phi3` | 各模型 benchmark |
| API 调用 | OpenAI-compatible API (`POST /api/chat`) | Ollama API 文档 |
| Embedding 模型 | `nomic-embed-text` / `bge-small` 用于记忆向量化 | Ollama embedding |

**验收标准**：调用 `curl http://localhost:11434/api/chat` 返回正确的 JSON 响应。

### 4.2 ReAct 推理模式

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| ReAct 原理 | `Thought → Action → Observation → ... → Final Answer` | [ReAct 论文](https://arxiv.org/abs/2210.03629) |
| Prompt 工程 | System Prompt 设计、Few-shot 示例、输出格式约束（JSON Schema） | OpenAI Prompt 工程指南 |
| JSON 输出约束 | 用 `json-mode` 或 grammar 强制 LLM 输出合法 Tool Call | LLM API 文档 |
| Fallback 机制 | LLM 输出非法时的兜底策略 | 本项目"决策中枢"设计 |

**验收标准**：LLM 收到"用户连续 2 次关闭弹窗"的情境，能正确输出 `{action: "escalate", level: 3}`。

### 4.3 记忆系统（Memory Palace）

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| 三层记忆架构 | 工作记忆（M1 HashMap）、情景记忆（M2 SQLite）、语义记忆（M3 向量） | 本项目"记忆宫殿"设计 |
| 记忆检索 | 快速查询 → SQL 查询 → 向量相似度搜索 | sqlite-vec / Chroma 文档 |
| 反思模块 | 干预结果 → 正/负反馈 → 策略调整 | 强化学习reward shaping |

**验收标准**：检索"上次类似场景什么策略有效"，返回历史记录并影响本次决策。

### 4.4 可选：VLM 屏幕理解

| 主题 | 深度目标 | 推荐学习资源 |
|------|----------|-------------|
| 多模态模型 | `llava` / `qwen2-vl` 本地部署 | Ollama 多模态模型 |
| 截屏 → 结构化 | 截屏编码 → VLM → "当前是娱乐还是工作" 判断 | - |
| 隐私考量 | 截屏不在网络传输，本地处理 | - |

**验收标准**：用 DXGI 截屏 + VLM 判断"当前屏幕内容是否与工作相关"，作为感知层的增强信号。

## 阶段五：路线分化（共 8-16 周，视路线而定）

> 阶段一~四 是两条路线共同的地基，阶段五按所选路线二选一。

---

### 路线 A：Aegis-Hermes（约 8 周 MVP）

**核心思路**：不造轮子，Hermes 负责认知，自己只做工具和皮肤。

| 模块 | 技术重点 | 投入时间 |
|------|----------|----------|
| Hermes Agent 配置 | System Prompt、Skill 文件、记忆 Schema、计划 Agent | 1 周 |
| Intervention MCP Server | 弹窗、遮罩、理由输入窗、进程冻结 | 1.5 周 |
| Perception MCP Server | Win 进程监控、Android App 检测 | 1 周 |
| Notification MCP Server | SMTP 邮件、Webhook 告警 | 0.5 周 |
| AndroidCtl MCP Server | 悬浮球通信、全屏遮罩、ForceStop | 1.5 周 |
| Tauri 桌宠 | 透明窗口、Live2D、情绪同步 | 1.5 周 |
| Flutter 悬浮球 | 悬浮球 UI、gRPC 通信、后台保活 | 1.5 周 |
| 集成联调 | 全链路测试、边缘 case | 1 周 |

**Aegis-Hermes 学习清单**：
- [ ] Hermes 框架安装与 Agent 创建
- [ ] MCP 协议规范（MCP Server 实现）
- [ ] Hermes Skill 文件编写（状态机 + 干预链）
- [ ] Hermes 记忆 Agent 配置（Schema 定义）
- [ ] Hermes 自动技能生成（auto_skill_generation）
- [ ] Python `fastmcp` 或 Rust `rmcp` 实现 MCP Server
- [ ] Win32 API 弹窗 / 进程操作
- [ ] Android AccessibilityService（或 LSPosed）
- [ ] Tauri 透明窗口 + WebSocket 通信
- [ ] Flutter 悬浮球 + gRPC 客户端
- [ ] `smtplib` / `httpx` 发送邮件和 Webhook
- [ ] Ollama 本地部署 + API 调用
- [ ] Prompt 工程（System Prompt + JSON 输出约束）

---

### 路线 B：Aegis-Native（约 14 周 MVP）

**核心思路**：全自研，每一行决策逻辑都在自己手里。

| 模块 | 技术重点 | 投入时间 |
|------|----------|----------|
| Rust 核心引擎 | 事件总线（tokio::sync）、规则引擎（DSL+JIT）、调度器 | 3 周 |
| 自研 ReAct 循环 | Decision Core、LLM 调用（Ollama HTTP）、JSON 输出解析 | 2 周 |
| 三层记忆实现 | M1 HashMap / M2 SQLite / M3 sqlite-vec | 2 周 |
| 状态机 | 7 个状态、转换逻辑、进入/退出钩子 | 1 周 |
| gRPC 服务 | tonic 完整实现、设备注册、双向流、心跳重连 | 1.5 周 |
| 跨端协议 | Protobuf Schema、TLS-PSK、mDNS 自发现 | 1 周 |
| Android Kotlin Daemon | gRPC 客户端、AIDL IPC、LSPosed 模块 | 2 周 |
| 干预插件 | Win32 API DLL / Android .so 插件 ABI | 1.5 周 |
| Tauri + Flutter | 同路线 A，但接入协议改为 gRPC | 1.5 周 |

**Aegis-Native 学习清单**：
- [ ] Rust 所有权与生命周期（通过 The Rust Book）
- [ ] tokio 异步编程（async/await、Channel、Mutex）
- [ ] tonic gRPC（Protocol Buffers、代码生成、双向流）
- [ ] 事件总线设计（优先级队列、背压、环形缓冲区）
- [ ] 规则 DSL 设计（YAML 解析 + rhai 脚本引擎）
- [ ] 自研 ReAct Loop（OBSERVE → RETRIEVE → REASON → EXECUTE → REFLECT）
- [ ] 三层记忆架构（M1 内存 / M2 SQLite / M3 向量）
- [ ] sqlite-vec 向量存储与检索
- [ ] 状态机实现（7 状态 + 转换规则 + 钩子）
- [ ] Windows Win32 API（进程枚举、MessageBox、LockWorkStation、DXGI 截屏）
- [ ] Android Kotlin（AIDL、Service、Foreground Service）
- [ ] LSPosed/Xposed Hook（Zygote Hook、startActivity 拦截）
- [ ] 插件 ABI（Rust FFI、Cargo plugin 系统）
- [ ] Tauri（Rust 后端 + Web 前端 + 透明窗口）
- [ ] Flutter（Android 悬浮球 + gRPC 客户端）
- [ ] Ollama API + Embedding + Prompt 工程
- [ ] 系统打包（Windows MSI/AppInstaller、Android APK）
