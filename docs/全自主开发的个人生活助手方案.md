**方案代号：Aegis-Native（原生之盾）**  
**定位**：从零自研的个人强干预数字管家系统，不依赖任何现成 Agent 框架  
**核心公式**：`自研事件总线 + 双轨决策引擎 + 三层记忆宫殿 + 插件化工具运行时`  
**设计哲学**：**每一行决策逻辑都掌握在自己手里**，没有框架黑箱，没有协议转换损耗，没有不可控的自动行为。

## 一、与 Hermes 方案的根本差异

| 维度 | Aegis-Hermes | Aegis-Native（本方案） |
|------|-------------|----------------------|
| **决策权归属** | Hermes 内部 ReAct，你配置 Prompt | 你写 ReAct Loop，LLM 只是推理器 |
| **记忆结构** | Hermes 自动管理，Schema 受限 | 自研三层记忆（工作/情景/语义），完全自定义 |
| **规则延迟** | 经 MCP + Hermes 路由，~100-500ms | 本地规则引擎硬编译，~5-10ms |
| **协议栈** | MCP + WebSocket + Hermes 内部总线 | 自研 gRPC 协议 + Rust 内存总线 |
| **Android 深度** | 通过 MCP 间接控制 | gRPC 直连 Kotlin Daemon，LSPosed 原生 Hook |
| **进化方式** | 依赖 Hermes 技能自动生成 | 自研反思模块，可接入强化学习（未来） |
| **开发周期** | 8 周 MVP | 14-16 周 MVP |
| **维护成本** | 低（跟随上游） | 高（全栈自主） |
| **最大优势** | 快 | **没有天花板** |

## 三、L3 核心引擎：六大子系统详解

这是全自研方案的灵魂，每一个子系统都自己掌握。

### 3.1 事件总线（Event Bus）

不是简单的消息队列，而是**带优先级、带路由、带背压**的流处理系统。

```rust
// 核心结构
pub struct AegisEvent {
    pub id: Uuid,
    pub timestamp: DateTime<Utc>,
    pub source: DeviceId,        // "win-desktop" / "android-node-1"
    pub channel: EventChannel,   // Input / Internal / System
    pub priority: Priority,      // P0实时 / P1普通 / P2后台
    pub payload: EventPayload,   // 结构化数据
    pub trace_id: Uuid,          // 全链路追踪
}

pub enum EventPayload {
    UserInput { text: String, modality: InputModality },
    BehaviorDetected { app: String, window_title: String, deviation: f32 },
    InterventionResult { level: u8, outcome: Outcome },
    SystemHeartbeat { device: DeviceId, load: f32 },
}
```

**特性**：
- **优先级抢占**：P0 事件（如"用户正在关闭安全进程"）可中断 P1 事件处理
- **事件溯源**：所有事件持久化到 SQLite（只增不改），支持事后复盘
- **背压机制**：当 LLM 推理阻塞时，新事件进入环形缓冲区，旧事件被采样压缩

### 3.2 规则引擎（Rule Engine）

**双模运行**：解释型 DSL（开发期）+ JIT 编译（运行期）。

```yaml
# rules/focus_guardian.yaml
rules:
  - id: R-1001
    name: "工作时间娱乐拦截"
    enabled: true
    priority: 100
    cooldown: 30s           # 30秒内同一规则不重复触发
    condition:
      and:
        - eq: ["${device.type}", "android"]
        - in: ["${app.package}", ["com.ss.android.ugc.aweme", "tv.danmaku.bili"]]
        - between: ["${time.now}", "09:00", "18:00"]
        - not: "${state.immune}"
        - lt: ["${memory.today_escape_count}", 5]
    actions:
      - type: escalate
        params: { level: 3, message: "工作时间禁止启动娱乐应用" }
      - type: notify
        params: { channel: email, template: "escape_alert" }
    else:
      - type: log
        params: { level: info, message: "免疫期或已超限，放行" }
```

**引擎实现**：
- 启动时加载所有 YAML → 构建 AST → 编译为 Rust 闭包（用 `rhai` 脚本引擎或自研表达式解析器）
- 运行时：事件进入 → 按优先级排序规则 → 逐条匹配 → 命中即执行 Action Chain
- **延迟目标**：< 10ms（纯本地，不走 LLM）

### 3.3 决策中枢（Decision Core）

自研 ReAct Loop，LLM 只是其中的一个函数调用。

```
┌─────────────────────────────────────────────────────────────┐
│                    Decision Core 循环                         │
│                                                              │
│  1. OBSERVE: 从事件总线获取最新 ContextSnapshot              │
│              ├─ 当前设备状态                                  │
│              ├─ 活跃窗口/App                                  │
│              ├─ 今日历史干预记录                              │
│              └─ 用户情绪标记（如上次输入了"烦死了"）           │
│                      ↓                                       │
│  2. RETRIEVE: 查询记忆宫殿                                    │
│              ├─ 工作记忆：当前会话上下文                        │
│              ├─ 情景记忆：最近 24h 的干预结果                   │
│              └─ 语义记忆：向量检索"类似场景下什么策略有效"      │
│                      ↓                                       │
│  3. REASON: 构造 Prompt → 调用 Ollama HTTP API               │
│              模型：qwen2.5:14b（本地）                        │
│              输出格式：强制 JSON Schema                        │
│              {                                               │
│                "thought": "用户连续2次逃避，上次Level 2无效",  │
│                "action": "escalate",                         │
│                "target_level": 4,                            │
│                "message": "...",                             │
│                "tools": ["lock_screen", "send_email"]        │
│              }                                               │
│                      ↓                                       │
│  4. EXECUTE: 解析 JSON → 调用工具运行时                        │
│              若 LLM 输出非法 → 回退到规则引擎兜底               │
│                      ↓                                       │
│  5. REFLECT: 记录结果到记忆宫殿                                │
│              若用户服从 → 正反馈强化                           │
│              若用户反抗 → 标记为"抵抗模式"，下次升级策略        │
└─────────────────────────────────────────────────────────────┘
```

**关键设计**：
- **LLM 只是顾问**：规则引擎可否决 LLM（如 LLM 建议锁屏，但规则说"免疫期内禁止锁屏"）
- **输出约束**：使用 `json-mode` 或 `grammar` 强制 LLM 输出合法工具调用，拒绝幻觉
- **本地优先**：所有推理通过 `http://localhost:11434` 走 Ollama，零外网依赖

### 3.4 记忆宫殿（Memory Palace）

三层存储，不是简单的数据库，而是**模拟人脑记忆机制**。

| 层级 | 名称 | 存储介质 | 容量 | 保留时间 | 用途 |
|------|------|----------|------|----------|------|
| **M1** | 工作记忆 | Rust `HashMap` + `DashMap` | ~100 条 | 当前会话 | 当前任务、免疫期状态、今日计数器 |
| **M2** | 情景记忆 | SQLite（时序表） | 无上限 | 永久 | 每次干预的完整记录（时间、级别、结果、理由） |
| **M3** | 语义记忆 | sqlite-vec（本地向量） | 无上限 | 永久 | 用户偏好、有效文案、逃避借口模式、任务关联度 |

**记忆检索流程**：
```
输入：当前情境 C
├── M1 命中？→ 直接返回（延迟 0ms）
├── M2 SQL 查询：SELECT * FROM interventions WHERE date='today' ORDER BY time DESC
│   → 返回今日逃避次数、上次干预级别、上次理由
└── M3 向量检索：embedding(C) → top-k 相似历史情境
    → 返回"上次类似场景，Level 3 有效，Level 2 被关闭"
```

**Embedding 生成**：本地部署 `nomic-embed-text` 或 `bge-small`，通过 Ollama 调用，不依赖外网。

### 3.5 调度器（Scheduler）

- **时间触发**：Cron 表达式解析（`tokio-cron-scheduler`），支持动态增删
- **事件触发**：订阅事件总线特定 Topic（如 `behavior.detected`）
- **自适应频率**：
  - 正常态：每 5 分钟扫描一次
  - 警戒态（检测到逃逸）：每 30 秒扫描
  - 战斗态（连续逃逸）：实时事件驱动，停止轮询

### 3.6 状态机（State Machine）

自适应分级干预状态机，与 Hermes 方案不同之处在于：**状态转换逻辑完全自研，可插入自定义钩子**。

```
States:
  IDLE        → 监控中，未检测到异常
  IMMUNE      → 免疫期（用户主动签到后）
  ALERT       → 检测到轻微偏离（弹窗提醒即可）
  ENGAGED     → 用户与系统对抗中（连续关闭弹窗）
  PUNISHED    → 已触发外部惩罚（邮件已发送）
  REST        → 系统投降，进入休息模式
  OFFLINE     → 设备失联/服务崩溃

Transitions:
  IDLE --(打开娱乐App)--> ALERT
  ALERT --(用户服从)--> IDLE
  ALERT --(用户关闭)--> ENGAGED
  ENGAGED --(输入理由)--> ALERT（降级观察）
  ENGAGED --(再次逃逸)--> PUNISHED
  PUNISHED --(锁屏结束)--> REST
  REST --(1小时超时)--> IDLE
  ANY --(用户主动签到)--> IMMUNE（2小时）
  ANY --(核心引擎崩溃)--> OFFLINE（fail-safe）
```

**自定义钩子示例**：
```rust
// 状态进入 PUNISHED 时，自动执行
on_enter_punished: |ctx| {
    // 1. 发送邮件（不可撤销）
    ctx.notify.send_email("escape_alert");
    // 2. 桌宠播放哭泣动画
    ctx.ui.set_pet_emotion(Emotion::Crying);
    // 3. 记录到日记
    ctx.memory.log_diary("今日第N次触发惩罚");
}
```

## 四、入口矩阵（Input Surface）

所有入口统一生成 `AegisEvent`，打入事件总线。

| 入口 ID | 名称 | 触发源 | 接入方式 | 优先级 | 数据格式 |
|---------|------|--------|----------|--------|----------|
| `IN-01` | **语音唤醒** | 用户主动 | Win: Porcupine 唤醒词 → Rust 音频线程 → 事件总线 | P0 | `UserInput { audio: bytes }` |
| `IN-02` | **全局热键** | 用户主动 | Win: `RegisterHotKey` → Rust 消息循环 | P0 | `UserInput { key: "Ctrl+Shift+A" }` |
| `IN-03` | **桌宠交互** | 用户主动 | Tauri WebSocket → Gateway → 事件总线 | P0 | `UserInput { text, click_pos }` |
| `IN-04` | **悬浮球点击** | 用户主动 | Flutter → gRPC → Gateway | P0 | `UserInput { action: "toggle_menu" }` |
| `IN-05` | **定时心跳** | 系统被动 | Rust `tokio::time` → 生成 `SystemHeartbeat` | P1 | `SystemHeartbeat` |
| `IN-06` | **行为检测** | 环境被动 | Win: Rust 轮询 `GetForegroundWindow` (500ms)<br>Android: Accessibility/LSPosed → Kotlin Daemon → gRPC | P1 | `BehaviorDetected { app, window, deviation }` |
| `IN-07` | **屏幕视觉** | 环境被动 | Win: DXGI 截屏 → Rust 编码 → 可选 VLM | P2 | `ScreenCapture { frame: base64 }` |
| `IN-08` | **外部 Webhook** | 第三方 | Rust `axum` HTTP Server → 事件总线 | P2 | `ExternalWebhook { payload: json }` |
| `IN-09` | **邮件回执** | 第三方 | IMAP 轮询 → 解析回复 → 事件总线 | P3 | `UserInput { text: "已完成" }` |

**扩展机制**：新增入口只需实现 `InputAdapter` trait，注册到 Gateway 的 `InputRegistry`。

## 五、出口矩阵（Output Surface）

出口由核心引擎直接调用，通过 Gateway 路由到对应设备。

| 出口 ID | 名称 | 目标 | 强度 | 调用路径 | 可撤销性 |
|---------|------|------|------|----------|----------|
| `OUT-01` | 边缘提醒 | Win/Android | ★☆☆☆☆ | 引擎 → Gateway → Tauri/Flutter Toast | 自动 |
| `OUT-02` | 桌宠情绪 | Win | ★☆☆☆☆ | 引擎 → Gateway → Tauri Live2D | 用户主动 |
| `OUT-03` | 居中弹窗 | Win/Android | ★★☆☆☆ | 引擎 → Intervention Plugin → Win32 MessageBox / Android Dialog | 单次点击 |
| `OUT-04` | 理由输入窗 | Win/Android | ★★★☆☆ | 引擎 → Intervention Plugin → 自定义模态窗 | 认知成本 |
| `OUT-05` | 倒计时遮罩 | Win/Android | ★★★★☆ | 引擎 → Intervention Plugin → 全屏不可跳过遮罩 | 时间成本 |
| `OUT-06` | 进程冻结 | Win | ★★★★☆ | 引擎 → Intervention Plugin → `NtSuspendProcess` | 需恢复 |
| `OUT-07` | App 强杀 | Android | ★★★★☆ | 引擎 → Android Daemon → `am force-stop` | 需手动重开 |
| `OUT-08` | 屏幕锁定 | Win/Android | ★★★★★ | 引擎 → Intervention Plugin → `LockWorkStation` / `input keyevent POWER` | 需密码 |
| `OUT-09` | 邮件发送 | 外部 | ★★★★★ | 引擎 → Notification Plugin → SMTP/Resend（异步线程） | **不可撤销** |
| `OUT-10` | IM 告警 | 外部 | ★★★★★ | 引擎 → Notification Plugin → Webhook | **不可撤销** |
| `OUT-11` | 音频警报 | Win/Android | ★★★☆☆ | 引擎 → Intervention Plugin → Beep / TTS | 物理静音 |

**出口编排器（Output Orchestrator）**：
- 引擎不直接调用出口，而是发送 `InterventionIntent` 给编排器
- 编排器根据**设备在线状态**（如 Android 离线则降级到 Win 弹窗）、**权限可用性**（如悬浮窗权限被系统回收）、**用户历史服从率**动态选择出口组合
- 支持**原子事务**：要么全部出口执行成功，要么全部回滚（邮件已发送除外）

## 六、跨端通信协议（Aegis Protocol）

自研协议，替代 Hermes 的 MCP + WebSocket 组合。

### 6.1 协议栈

```
应用层：Aegis Protobuf Schema（消息、指令、事件）
传输层：gRPC over HTTP/2（双向流）
发现层：mDNS（局域网设备自发现）
安全层：TLS-PSK（预共享密钥，局域网内简单加密）
```

### 6.2 核心 Proto 定义

```protobuf
// aegis.proto
service AegisGateway {
  // 设备注册
  rpc Register(DeviceInfo) returns (SessionToken);
  
  // 双向流：设备 ↔ 主脑
  rpc Stream(stream Message) returns (stream Message);
  
  // 心跳
  rpc Heartbeat(HeartbeatReq) returns (HeartbeatRsp);
}

message Message {
  string trace_id = 1;
  int64 timestamp = 2;
  oneof payload {
    Event event = 10;
    Command command = 11;
    Response response = 12;
  }
}

message Event {
  string source_device = 1;
  string event_type = 2;      // "behavior_detected", "user_input"
  bytes json_payload = 3;     // 结构化 JSON
}

message Command {
  string target_device = 1;
  string command_type = 2;    // "show_overlay", "send_email"
  bytes json_payload = 3;
  int32 timeout_ms = 4;       // 超时未响应则降级
}
```

### 6.3 通信拓扑

```
[Windows 主脑: aegis-core.exe]
    ├── gRPC Server (0.0.0.0:50051)
    ├── mDNS 广播 "_aegis._tcp.local."
    │
    ├──←→ [Tauri 桌宠]        (WebSocket localhost:8765)
    ├──←→ [Android 手机]      (gRPC over WiFi)
    └──←→ [未来: Linux/Mac 节点] (gRPC)
```

**降级策略**：若 gRPC 断开，Android 端 Kotlin Daemon 进入**离线自治模式**——只执行本地硬规则（如打开抖音直接遮罩），等网络恢复后同步事件日志。

## 七、Android 深度整合架构

因为可 Root，Android 端不是"普通 App"，而是**系统级守护进程**。

```
┌─────────────────────────────────────────────┐
│              Android 用户层                  │
│  ┌──────────────┐  ┌──────────────────────┐ │
│  │ Flutter UI   │  │ 系统设置入口          │ │
│  │ (悬浮球)      │  │ (LSPosed模块开关)     │ │
│  └──────┬───────┘  └──────────────────────┘ │
│         │  MethodChannel                    │
├─────────┼───────────────────────────────────┤
│         ↓  Android Service 层               │
│  ┌──────────────────────────────────────┐   │
│  │      AegisDaemon (Kotlin)            │   │
│  │  • gRPC Client (连接PC)              │   │
│  │  • AccessibilityService (备用感知)    │   │
│  │  • WindowManager (悬浮球/遮罩)        │   │
│  │  • NotificationListener (消息回执)    │   │
│  └──────────────┬───────────────────────┘   │
│                 │ Binder IPC                │
├─────────────────┼───────────────────────────┤
│                 ↓ 系统框架层 (Root)          │
│  ┌──────────────────────────────────────┐   │
│  │      LSPosed 模块 (Zygote Hook)      │   │
│  │  • Hook ActivityManager.startActivity │   │
│  │    → 拦截黑名单App启动                │   │
│  │  • Hook WindowManager.addView         │   │
│  │    → 注入管家遮罩（系统级，不可绕过）   │   │
│  │  • Hook PowerManager.goToSleep        │   │
│  │    → 支持强制锁屏                     │   │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

**关键**：LSPosed 模块在系统框架层运行，即使 Flutter App 被杀死，Hook 仍然生效。Flutter 只是**配置界面和状态显示**。

CREATE TABLE daily_stats (
    date TEXT PRIMARY KEY,
    planned_task TEXT,
    escape_count INTEGER DEFAULT 0,
    max_level INTEGER DEFAULT 0,
    compliance_rate REAL DEFAULT 0.0,
    focus_minutes INTEGER DEFAULT 0
);

-- 语义记忆（向量检索）
CREATE TABLE semantic_memory (
    id TEXT PRIMARY KEY,
    embedding BLOB,          -- 768维 float32
    content TEXT,
    memory_type TEXT,        -- "excuse", "effective_message", "preference"

);

## 九、MVP 迭代路线（14 周产品化）

| 周次 | 阶段 | 核心目标 | 交付物 |
|------|------|----------|--------|
| **W1** | **骨架** | Rust 核心引擎编译通过；事件总线跑通；SQLite 建表 | `aegis-core.exe` 能启动，能发事件，能记日志 |
| **W2** | **感知** | Win32 进程监控；Android Accessibility 读取前台 App | 打开 B站 → 事件总线出现 `BehaviorDetected` |
| **W3** | **干预** | Intervention Plugin：Win 弹窗（Level 1~2）；理由输入窗（Level 3） | 弹窗出现，关闭后记录到数据库 |
| **W4** | **规则** | 规则引擎 YAML 解析 + JIT 执行；第一条硬规则跑通 | 配置规则 → 打开娱乐 App → 自动弹窗 |
| **W5** | **通信** | gRPC 双向流打通；Android Flutter 连接 PC | 手机点击悬浮球 → PC 收到事件 |
| **W6** | **状态机** | 分级干预状态机完整实现；Level 4 邮件惩罚 | 连续关闭 3 次 → 收到邮件 |
| **W7** | **大脑** | 接入 Ollama HTTP；自研 ReAct Loop；决策中枢跑通 | LLM 能根据历史数据决定干预级别 |
| **W8** | **记忆** | 三层记忆实现；向量检索接入；反思模块 | "上次类似场景 Level 2 无效" 被检索到 |
| **W9** | **Android 深度** | LSPosed 模块开发；系统级 App 拦截；全屏遮罩 | 打开抖音 → 系统级遮罩，无法返回 |
| **W10** | **桌宠** | Tauri 透明窗口；Live2D 嵌入；情绪同步 | 弹窗时桌宠变红/抖动 |
| **W11** | **自适应** | 根据服从率自动调整规则参数；生成日报 | 系统开始"懂你"，减少无效打扰 |
| **W12** | **视觉** | DXGI 截屏；可选 VLM 分析屏幕内容 | 截图识别"你在写代码还是看视频" |
| **W13** | **打磨** | 配置界面；规则编辑器；数据看板 | 非技术用户也能改规则 |
| **W14** | **固化** | 安装包打包；开机自启；崩溃自恢复 | 双击安装，开机自动守护 |

## 十、与 Hermes 方案的终极对比

| 决策维度 | Aegis-Hermes | Aegis-Native |
|---------|-------------|--------------|
| **控制权** | 你配置，它决策（黑盒） | 你写决策逻辑，LLM 只推理（白盒） |
| **延迟** | 100-500ms（MCP+框架开销） | <10ms 规则 / <2s LLM（直连） |
| **定制深度** | 受限于 Hermes Skill 语法 | 无限制，可改到内核 |
| **数据隐私** | Hermes 可能上传遥测（需审查） | 完全本地，代码自己审计 |
| **长期演进** | 跟随 Hermes 路线图 | 可接入 RLHF、强化学习、自定义模型 |
| **工程风险** | 低（框架兜底） | 高（自己处理并发、内存、崩溃） |
| **适合场景** | 快速验证、接受框架约束 | 长期主义、追求极致、技术可控 |
